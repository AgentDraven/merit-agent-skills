What “good” looks like in the PRD
  • Identity complete — name, slug, one-line promise, audience, live app URL.
  • Hero-ready marketing — brand, one headline, one supporting sentence, one primary CTA.
  • Small Must FRs — testable rows with stable IDs (FR-01…).
  • Clear boundary — features in app_logic/; rails stay on merit-prod.
Anti-patterns to avoid
  • Laundry lists of what you are not doing on the happy path.
  • Dashboard clutter in the first viewport (stats strips, card grids, floating badges).
  • Secrets, API keys, or app code inside portal/.
  • Forking auth/store/payments into app_logic/.
  • Claiming Plus/commerce “over dinner” before the store tenant is live.
  • Impersonal “tenant” voice when “your app” / “your store” works.

Make Art (foundational)

  • Brand first — product name is a hero-level signal.
  • One composition — first viewport: brand, headline, one sentence, one CTA group.
  • Seamless flow — one obvious next step; fewer clicks.
  • Non-geeky voice — insight first; geek detail one click deeper.
  • Be personal — speak to you / your app / your store.
  • Cloud first — the product host is the live URL, not a laptop preview.

Build app_logic/ on the MERIT ecosystem

You write product features. MERIT supplies rails, packages, and patterns other apps already use. Start from the Developer Center guides, then copy patterns from live consumer apps.

Developer Center · Providers · PAR packages · meritutils registry

Provider rails (via merit-prod)

  • merit-prodGateway host for your app UI (/apps/<id>/play), health, and route map. /api/health
  • meritutilsPinned UI packages on the PAR CDN — workbench, journal, AMA, leaderboard, usage meter, merit_ux / Gloss themes. Pin through the gateway; do not vendor provider bytes.
  • meritsubsSubscriber identity, Free/Plus tiers, entitlements, usage. Mount: /api/meritsubs/*.
  • meritstoreRegistration, SKUs, checkout, ledger. Paths: /store/<id>/ + /api/meritstore/*.
  • Tenant planeShared item APIs isolated by consumer_id (/api/tenant/*). Server-to-server only.

Packages to leverage in app_logic / play

  • merit_workbenchGrid, inspector, action bar, themes, admin-gate UI, field schema — advanced toolchain shell. Pin via dinner par scaffold.
  • journalPrompt-anchored compose + local-first history on the workbench.
  • merit_journalJournal package variant on the same CDN family.
  • merit_amaQ&A / AMA primitives — bring your presentation layer.
  • merit_leaderboardRanking / scoreboard primitives.
  • merit_usage_meterUsage display hooks for freemium / Plus honesty.
  • merit_uxShared UX helpers + Gloss theme CSS (aurora / graphite / daylight).

How to use these examples while building
  • Copy structure, not secrets — observe portal vs app_logic boundaries; never paste keys.
  • Pin packages — match versions from registry.json / your cfg/par_pins.json.
  • Reuse toolchains — merit_workbench + journal for operator/creator consoles; AMA/leaderboard for community loops; usage meter for Free/Plus honesty.
  • Adopt sister products — use DIRT when you need digital-income / content ops; use CAST patterns when your venture is podcast / show oriented.
  • Stay on rails — auth, store, payments remain meritsubs / meritstore on merit-prod; your differentiator stays in app_logic.
